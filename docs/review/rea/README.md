# REA analysis artifacts (2026-10-21)

Everything in this directory was produced by
[REA](https://github.com/morluto/rea) (v6.5.0) against the native
QTranslate 6.10.0 binary, plus the payload extraction the REA results
depended on.

REA needs **Ghidra** (12.1.4, `GHIDRA_INSTALL_DIR`) and a **JDK 21+**
(`JAVA_HOME`); on this host:

```bash
export GHIDRA_INSTALL_DIR=/opt/homebrew/Cellar/ghidra/12.1.4/libexec
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
```

## What is here

| Path | What it is |
|---|---|
| `analyze.json` | `rea analyze` on the native PE — the binary overview (8468 procedures, 3448 strings, 7 segments) |
| `qtranslate.snapshot` | REA's analysis snapshot for that binary |
| `pe_resources.json` | `rea inspect-pe-resources` — the EXE's resource tree (84 resources, 24 icon groups) with every payload's file range and hash |
| `decomp/*.json` | `rea decompile` of the procedures the open checklist items name |
| `js_root/` | the 25 recovered native JS/asset files (19 `Services/*/Service.js`, `Common.js`, 4 history exporters, the XSLT) |
| `service_icons/` | the 18 service icons recovered from the installer payload, as PNGs, with `_manifest.json` and `_pairs.png` (native icon beside its match) |
| `ui_icons/` | the 25 icon groups recovered from the EXE's RT_ICON resources, with `_matches.json` |
| `uses_auto_detect_table.json` | native's per-service `usesAutoDetectCode` truth table, measured from `js_root` |
| `js_compare.json` | `rea compare-source-to-bundle` — the port's source tree against the native JS Evidence |

## What is NOT here (and why)

`js_analysis.json` (16 MB) and `js_compare_input.json` (17 MB) are
regenerated by:

```bash
rea analyze-javascript-application docs/review/rea/js_root \
    --artifact-format directory --format json > docs/review/rea/js_analysis.json
```

and

```bash
python3 - <<'PY'
import json, sys
sys.path.insert(0, "tools/_scratch")
from rea_eid import authenticate
lines = open("docs/review/rea/js_analysis.json", encoding="utf-8").read().splitlines()
app = json.loads(lines[-1])
ref = json.load(open("docs/review/rea/ref_full.json"))
if app.get("environment") is None:
    app["environment"] = {"id": "local-macos-arm64-analysis",
                           "platform": "darwin", "architecture": "arm64",
                           "isolation": "none"}
    app = authenticate(app)
json.dump({"reference": ref, "application": app},
          open("docs/review/rea/js_compare_input.json", "w"))
PY
rea compare-source-to-bundle docs/review/rea/js_compare_input.json \
    --format json > docs/review/rea/js_compare.json
```

`tools/_scratch/rea_eid.py` recomputes REA's Evidence semantic identifier
(RFC 8785-style canonical JSON over the record's semantic projection,
SHA-256, `ev_` prefix) so a record can be re-stamped after an environment
binding is added — REA's own validator rejects a record whose id does not
match its content.

`ref_full.json` comes from `rea import-reference-source qtranslate --detail
full`.

## The three findings REA produced

1. **`usesAutoDetectCode` is a framework function, not a per-service hook.**
   It lives in `Services/Common.js` and tests
   `SupportedLanguages[AUTO_DETECT_LANGUAGE] !== UNKNOWN_LANGUAGE_CODE`
   (`AUTO_DETECT_LANGUAGE = 1`). That makes native's per-service truth
   table *derivable*, which is what closed the checklist's
   "not verified" item and replaced the port's hand-listed capability set.
   → `docs/review/auto_detect_capability_table.json`,
   `docs/review/AUTO_DETECT_CAPABILITY_2026-10-21.md`.

2. **The EXE's RT_ICON resources hold native's own UI icons** — the
   application icon (group 0, matching the title-bar icon at ssd 144) and
   the microphone/headphone the main window overlays on its panes. They are
   now bundled in `qtranslate/assets/`.

3. **The JS application graph** (10,373 semantic nodes, 9,675 relations,
   276 fingerprints) is a machine reconstruction of native's scriptable
   layer — the 19 services, their language tables, their request builders
   and their capabilities.
